# huh: working notes

Living log of decisions, gotchas and what's left. Newest decisions at the bottom of each section.

## Layout
```
src/Huh.App          WinUI 3 tray app + bubble (assembly "Huh", namespace "Huh")
src/Huh.Core         UI-free: detection, dialog model, decoding, provenance, AI, privacy, actions
tools/Huh.TestHarness  raises error / non-error dialogs on demand (console, comctl32 v6 manifest)
tools/Huh.Probe      headless host for Core detection; JSONL log + harness scoring
tests/Huh.Tests      xUnit v3 (Microsoft.Testing.Platform runner)
```

## Build & run
- Build: `dotnet build Huh.slnx -c Debug -p:Platform=x64`
- Tests: `dotnet test --project tests/Huh.Tests`
- App:   `src/Huh.App/bin/x64/Debug/net10.0-windows10.0.26100.0/win-x64/Huh.exe`

## Decisions
- **.NET 10** (`net10.0-windows10.0.26100.0` for the app, `net10.0-windows` elsewhere). .NET 8 support ends 2026-11-10.
- **Unpackaged + self-contained Windows App SDK** (`WindowsPackageType=None`, `WindowsAppSDKSelfContained=true`) so the app
  can be launched/killed/screenshotted from the CLI. `EnableMsixTooling` stays on (needed for resources.pri). MSIX is optional (M6).
- Project renamed to **Huh.App**, but `AssemblyName=Huh` / `RootNamespace=Huh` to avoid a `Huh.App.App` namespace/type clash.
- Platforms: x64 + ARM64 (x86 dropped). Libraries are AnyCPU.
- Removed the template's `systemAIModels` capability: no NPU on the target machine (i7-1355U), so Windows AI APIs are unavailable.
- **Central package management** (`Directory.Packages.props`).
- **UI Automation via raw COM generated by CsWin32**, not FlaUI: FlaUI depends on tlbimp interop (built-in COM), which is
  disabled under trimming (Release publish trims). Raw COM also gives explicit control of UIA threading.
- **Tray icon via raw Shell_NotifyIcon** (H.NotifyIcon.WinUI is pre-release only).
- **Gemini default model `gemini-3.8-flash`, fallback `gemini-3.5-flash-lite`** (free tier per Google's pricing page, checked 2026-11-05).
  `gemini-2.5-flash` is deprecated (rerouted 2026-12-01). Free-tier data IS used by Google to improve products.
- **AI is opt-in**: nothing goes to Gemini until the user accepts on the first-run screen (which explains free-tier data use).
  Deterministic info (codes, source program, signature) works without AI.
- **Re-run as admin**: exe path only, never arguments. Blocked for unsigned binaries; override shows a red warning with the path + "unsigned".
- AI-chosen actions carry parameters that are validated (ms-settings from a fixed list, folders must exist locally, search query built by huh).
  Dialog text is untrusted input (prompt-injection vector).

### M1 detection design
- `DialogMonitor` (Core) = WinEvent hooks (own thread + message loop) + UIA WindowOpened (desktop subtree) feeding ONE MTA
  worker thread. Hook callbacks only filter/forward; UIA reads happen on the worker (never on a UI/STA thread).
- Cheap pre-filter before any UIA call: class `#32770`, known dialog classes (`OperationStatusWindow`), DIALOGSTART/ALERT,
  UIA IsDialog, or an error-ish title. Everything else is skipped.
- Content is read **only via UIA** (one `FindAllBuildCache` round trip). Win32 is used for metadata only: class, caption,
  pid, and the MessageBox icon's *resource id* (`STM_GETICON` + `GetIconInfoEx`; no pixels).
- Classifier is pure and unit-tested: error words / error codes / error icon > question phrasing > warning > info.
- De-dupe: same hwnd, or same (pid, title, message), within 3 s. Own process always ignored.
- UIA timeouts set to 1.5 s (IUIAutomation2) so a hung app can't stall the worker; reads retry 3x with backoff.
- Verified with `Huh.Probe score`: 28/28 error dialogs, 0/6 false positives, three consecutive runs; p50 ~167 ms.
  Idle cost ~0.9% of one core, 37 MB. Report: `docs/reports/m1-detection.md`.
- Caveat: the text rules were written before the first run, but the harness and the rules come from the same author.
  Real-world precision will be lower; the per-app exclusion list (M6) is the safety valve.

### M2 bubble design
- Dev display: one 14" 1920x1200 panel at **125% (120 DPI)**, work area 1920x1140. Mixed-DPI placement is covered by unit
  tests on fake monitor geometry (no second monitor available).
- `BubblePlacer` (Core, pure): bubble size in DIPs, converted with the DPI of the monitor the bubble *lands on*; prefers
  right > left > below > above > overlap-the-corner; slides along the dialog edge to stay in the work area; when it spills
  onto a neighbouring monitor it's pushed fully onto it (away from the dialog, never over it).
- `WindowFollower` (Core): out-of-context hooks scoped to the dialog's pid/tid for LOCATIONCHANGE, SHOW/HIDE and
  MINIMIZESTART/END, plus global FOREGROUND. Created on the UI thread (WinUI pumps Win32 messages, so callbacks arrive there).
- `BubbleWindow` (App): OverlappedPresenter with border but no title bar (keeps the native shadow + rounded corners),
  `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`, `IsShownInSwitchers=false`, shown with `SW_SHOWNOACTIVATE` (never `Activate()`).
  Height is content-driven (XAML measure at 340 DIP wide), re-placed on size change.
- Z-order: directly above its dialog (not topmost) unless the dialog itself is topmost. An unrelated window covering the
  dialog also covers the bubble.
- `AlwaysActiveAcrylic`: custom SystemBackdrop with `IsInputActive=true` and higher tint/luminosity opacity than the default
  (the stock acrylic was unreadable over busy content).
- App has no main window: `DispatcherShutdownMode.OnExplicitShutdown`. Diagnostics log at `%LOCALAPPDATA%\huh\logs\huh.log`
  (events only, never dialog text). `HUH_THEME=Light|Dark` forces a theme for testing.
- Verified with `Huh.Probe bubble` (46 checks over 5 dialog types: focus never stolen, styles, placement == placer to the pixel
  at 5 positions + a simulated drag, z-order incl. a covering window, minimize/restore of the owner, close). 46/46 in 5
  consecutive runs, dark and light theme. Report: `docs/reports/m2-bubble.md`. Screenshots stay in `artifacts/` (they show the
  dev's user path in the bubble, so they're not committed).

## Gotchas
- `SupportedOSPlatformVersion` can't be set globally: `net10.0-windows` has TargetPlatformVersion 7.0 (NETSDK1135).
- .NET 10 SDK: `dotnet test` needs `"test": {"runner": "Microsoft.Testing.Platform"}` in global.json for xUnit v3; use `dotnet test --project ...`.
- TaskDialog needs a Common Controls v6 manifest dependency (harness has one).
- Mica/Acrylic render the inactive fallback in a never-activated window, so force `IsInputActive=true` (M2).
- `Window.Activate()` steals focus, so show the bubble with `SW_SHOWNOACTIVATE` (M2).
- CsWin32: `CsWin32RunAsBuildTask=true` + `allowMarshaling:true` gives `[GeneratedComInterface]` COM (trim-safe).
  `allowMarshaling:false` gives raw vtable structs instead. Some shell structs (SHELLEXECUTEINFOW) need a concrete PlatformTarget.
- **UIA does not expose the icon type** of a MessageBox (unnamed Static image) or TaskDialog ("MainInstructionIcon").
  `STM_GETICON` handles don't match `LoadIcon(NULL, IDI_*)` (MessageBox loads DPI-scaled copies), but `GetIconInfoEx` resource ids
  do: imageres #98 error, #84 warning, #81 info, #99 question (module name is a datafile handle string); csrss hard-error boxes use
  user32 #32513..32516. TaskDialog icon type is still unknown, so TaskDialogs rely on text cues.
- `EVENT_SYSTEM_SOUND` never fired for MessageBox on this machine, so it's not usable as a severity signal.
- TaskDialog: UIA hides `DirectUIHWND`; identify it by AutomationIds (`MainInstruction`, `ContentText`, `CommandButton_*`).
- Caption buttons can have AutomationIds like `Minimize-Restore`; filter by prefix + empty ClassName.
- Explorer text contains U+200E bidi marks; strip Unicode Format chars.
- msiexec's dialog times out (`0x80131505`) on the first UIA read while the process starts up, so reads must retry.
- Shell "File In Use" is an `OperationStatusWindow` (not #32770) and only appears if another process holds the lock and the
  IFileOperation has an owner window.
- The csrss hard-error box ("code execution cannot proceed") IS readable from medium IL.
- **Invisible resize borders**: SetWindowPos sizes the *outer* rect; a bordered window's visible frame is inset (8 px at
  125%). Compensate with GetWindowRect vs DWMWA_EXTENDED_FRAME_BOUNDS.
- **EVENT_SYSTEM_FOREGROUND arrives before the new foreground window is raised**, so re-stack again ~120 ms later.
- **Minimizing a dialog's owner HIDES the dialog** (no destroy). Treating HIDE as close killed the bubble for good (content
  de-dupe then blocked re-detection). Only EVENT_OBJECT_DESTROY means closed; the bubble follows SHOW/HIDE itself.
- A dialog can be destroyed before the UI thread gets to its bubble (cold XAML start): check the dialog still exists before
  creating/showing a bubble.
- XAML type-info generator tries to `new` public property types of a Window: keep `DialogInfo` properties internal.
- A process started by the probe inherits the probe's stdout; if the probe dies without killing it, `| grep` never sees EOF.
- TaskDialogs without a Cancel button ignore WM_CLOSE.
- First launch after a rebuild can take ~12 s to reach OnLaunched (most likely Defender scanning new binaries); normally ~0.7 s.
  First bubble after start ~0.6-1.7 s (XAML cold start); later bubbles 85-270 ms.
- Harness `run` scenarios that spawn helpers (rundll32/regsvr32/msiexec) report the helper's process; the probe matches by name.

## UIPI (verified 2026-11-06)
Elevated harness (`Start-Process -Verb RunAs`) + non-elevated probe: the dialog IS detected (WinEvents cross integrity levels),
caption and UIA `IsDialog` are readable, but the UIA subtree is empty and `STM_GETICON` is blocked.
`OpenProcessToken` still works on a same-user elevated process, so we see `Elevation=Elevated` and set `BlockedByUipi=true`.
Retries are skipped for elevated/AccessDenied targets (they'd only add ~1.5 s). huh can't close or click such dialogs either.
